# 1. 이번 문서의 위치

이 문서는 **실행 파일을 당장 대수술하는 문서가 아니다.**  
먼저 아래를 판정하는 문서다.

- 어떤 파일이 어떤 역할을 하는가
- 어떤 순서로 실행되는가
- 환경변수는 어디서 읽는가
- API / Frontend / Tkinter가 같이 실행되면 무엇이 충돌하는가
- P0-4에서 어떤 파일만 최소 수정하면 되는가

즉, 이번 문서는 **“실행 루프 구조 판정표”**다.

# 2. 실행 파일 점검 원칙

## 2-1. 절대 원칙
```text
- 실행 파일을 바로 크게 고치지 않는다
- 먼저 실제 역할과 연결 구조를 문서화한다
- Tkinter / API / Frontend 각각의 진입점을 분리해서 본다
- .env는 "누가 / 언제 / 어떻게" 읽는지 따진다
- 포트 / DB lock / 경로 / 로그 파일 충돌 가능성을 먼저 찾는다
```

## 2-2. 이번 단계에서 우선 보는 대상
```text
1. run.py
2. run_bootstrap.py
3. run_react_api.py
4. run_react.bat
5. .env
6. .env.example 또는 settings/config 계열 파일
```

# 3. 왜 이 점검이 필요한가

마스터 문서는 핵심 파일/경로로 아래를 명시하고 있다.

- `run.py`
- `run_bootstrap.py`
- `run_react.bat`
- `run_react_api.py`
- `.env` 분리
- BOT_TOKEN / CHAT_ID / ADMIN_TOKEN 분리
- Pre-Test 후 실행, 실패 시 중단  
fileciteturn10file0 fileciteturn10file1

또한 BAT / PowerShell / MASTER 통합 구조를 아래처럼 요구한다.

```text
BAT / PS1
→ 사전 테스트
→ Telegram Bridge 실행
→ bridge 내부에서 Claude 실행
→ Claude는 MASTER.md 기준으로 작업
```

즉, 실행 체계가 불명확하면 아래 문제가 발생한다.

```text
- React는 뜨는데 API가 안 뜸
- API는 뜨는데 .env 값을 못 읽음
- Tkinter와 React가 같은 DB를 동시에 잡아 lock 발생
- run_react.bat는 돌지만 오류 로그가 남지 않음
- run.py / run_bootstrap.py 역할 중복으로 진입 순서가 꼬임
```

# 4. 점검 대상별 역할 판정표

| 파일 | 예상 역할 | 실제 확인해야 할 것 | 중요도 |
|---|---|---|---|
| `run.py` | Tkinter 메인 실행 진입점 | 앱 생성 / mainloop / bootstrap 호출 여부 | 매우 높음 |
| `run_bootstrap.py` | 사전 초기화 / 환경 점검 | DB 준비 / 경로 준비 / 설정 로드 여부 | 높음 |
| `run_react_api.py` | FastAPI 실행 진입점 | uvicorn 실행 / host / port / env 로드 | 매우 높음 |
| `run_react.bat` | Windows용 통합 실행 배치 | API + Frontend 실행 순서 / 병렬 여부 | 매우 높음 |
| `.env` | 환경변수 저장소 | 누가 로드하는지 / 키 종류 / 경로 | 매우 높음 |
| config/settings 파일 | 보조 설정 | `.env`와 중복 여부 | 중간 |

## 1. 시스템 소개

### 1.1 개요

SQM 재고관리 시스템은 리튬카보네이트(Lithium Carbonate)와 니켈설페이트(Nickel Sulfate) 
재고를 관리하기 위한 전문 시스템입니다.

### 1.2 주요 특징

| 기능 | 설명 |
|------|------|
| **All-or-Nothing 처리** | 오류 발생 시 전체 작업 취소로 데이터 무결성 보장 |
| **Preflight 검증** | 실제 처리 전 사전 검증으로 오류 예방 |
| **AI 문서 파싱** | Gemini AI로 PDF 문서 자동 인식 |
| **톤백 단위 관리** | LOT별 톤백 개별 추적 |
| **자동 백업** | 주기적 자동 백업으로 데이터 안전 |

### 1.3 v3.2 신규 기능

- ✅ **📊 대시보드 탭**: 시작 시 첫 화면으로 요약 정보 표시
- ✅ **🎨 flatly 테마**: 고급스러운 녹색/회색 기본 테마
- ✅ **커스텀 메뉴바**: ttkbootstrap 기반 컴팩트한 메뉴
- ✅ **톤백 부분출고 불가**: 톤백은 전량 출고만 가능 (데이터 정확성 향상)
- ✅ **OCR 자동 튜닝**: API 오류 시 자동으로 처리 속도 조절
- ✅ **작업 자동 복구**: 비정상 종료 시 미완료 작업 복구 제안
- ✅ **부드러운 진행률**: 공유폴더 사용 시에도 끊김 없는 진행률 표시
- ✅ **자동 새로고침**: 대시보드 30초 주기 자동 갱신

## 2. 설치 및 실행

### 2.1 시스템 요구사항

- Windows 10/11 (64bit)
- Python 3.10 이상
- 메모리: 4GB 이상 권장
- 저장공간: 500MB 이상

### 2.2 설치 방법

```bash
# 1. 압축 해제
# sqm_v3.2.zip을 원하는 폴더에 압축 해제

# 2. 의존성 설치
pip install -r requirements.txt

# 3. 실행
python run.py
# 또는
SQM_실행.bat  # Windows 배치 파일
```

### 2.3 첫 실행 설정

1. 프로그램 첫 실행 시 데이터베이스가 자동 생성됩니다.
2. 설정 메뉴에서 Gemini API 키를 입력하세요 (AI 문서 파싱 사용 시).
3. 백업 폴더 위치를 설정하세요.

## 4. 입고 처리

### 4.1 PDF 문서로 입고

가장 권장하는 방법입니다. Packing List PDF를 업로드하면 자동으로 데이터를 추출합니다.

**단계:**

1. **메뉴** → **파일** → **PDF 입고** 또는 툴바의 **[입고]** 버튼 클릭
2. PDF 파일 선택 (Packing List, Invoice 등)
3. AI가 자동으로 데이터 추출
4. **미리보기** 화면에서 데이터 확인
5. **확인** 버튼으로 입고 처리

```
┌─────────────────────────────────────────┐
│  PDF 입고 미리보기                      │
├─────────────────────────────────────────┤
│  LOT 번호: 2024-LC-001                  │
│  제품명: Lithium Carbonate              │
│  총 중량: 25,000 kg                     │
│  톤백 수: 25개                          │
│  입고일: 2024-01-15                     │
├─────────────────────────────────────────┤
│  톤백 목록:                             │
│  ┌────────────┬──────────┐             │
│  │ 톤백 ID    │ 중량(kg) │             │
│  ├────────────┼──────────┤             │
│  │ TB-001     │ 1,000    │             │
│  │ TB-002     │ 1,000    │             │
│  │ ...        │ ...      │             │
│  └────────────┴──────────┘             │
├─────────────────────────────────────────┤
│           [취소]  [확인]                │
└─────────────────────────────────────────┘
```

### 4.2 Excel로 입고

대량 입고 시 Excel 파일을 사용합니다.

**단계:**

1. **메뉴** → **파일** → **Excel 입고**
2. Excel 파일 선택
3. 데이터 매핑 확인
4. **입고 처리** 버튼 클릭

**Excel 형식:**

| LOT번호 | 제품명 | 중량(kg) | 입고일 | 톤백수 | 비고 |
|---------|--------|----------|--------|--------|------|
| 2024-LC-001 | Lithium Carbonate | 25000 | 2024-01-15 | 25 | |

### 4.3 수동 입고

개별 항목을 직접 입력합니다.

1. **메뉴** → **편집** → **수동 입고**
2. 필수 항목 입력:
   - LOT 번호 (필수, 고유값)
   - 제품명 (필수)
   - 중량 (필수)
   - 입고일 (필수)
3. **저장** 버튼 클릭

### 4.4 입고 시 주의사항

⚠️ **LOT 번호는 중복될 수 없습니다.**

⚠️ **입고 완료 후에는 LOT 번호 변경이 불가합니다.**

⚠️ **톤백은 자동 생성됩니다.** (중량을 톤백 수로 균등 분배)

## 5. 출고 처리

### 5.1 출고 워크플로우

```
[출고 요청] → [Preflight 검증] → [미리보기] → [확인] → [출고 완료]
                   ↓
              실패 시 오류 표시
```

### 5.2 일반 출고

1. **재고** 탭에서 출고할 LOT 선택
2. **우클릭** → **출고** 또는 툴바 **[출고]** 버튼
3. 출고 정보 입력:
   - 출고량 (kg)
   - 출고일
   - 고객사
   - 차량번호 (선택)
4. **Preflight 검증** 자동 실행
5. 검증 통과 시 **출고 확인**

### 5.3 Preflight 검증

출고 전 자동으로 검증을 수행합니다:

| 검증 항목 | 설명 |
|-----------|------|
| 재고 확인 | 출고량이 현재 재고를 초과하지 않는지 |
| 톤백 가용성 | 출고 가능한 톤백이 충분한지 |
| LOT 상태 | LOT이 출고 가능 상태인지 |
| 중량 정합성 | 데이터 무결성 검증 |

### 5.4 톤백 출고 규칙 (v3.2)

⚠️ **핵심 규칙: 톤백 부분 출고 불가**

| 상황 | 처리 방식 |
|------|----------|
| 톤백 전체 출고 | ✅ 허용 |
| 톤백 일부 출고 | ❌ 불가 |

**예시:**
- 1,000kg 톤백에서 500kg만 출고 → ❌ 불가
- 1,000kg 톤백 전량 출고 → ✅ 가능

**출고량 < 톤백 무게일 경우:**
- 시스템이 최적의 톤백 조합을 자동 선택
- 정확히 맞는 조합이 없으면 경고 표시

### 5.5 출고 미리보기

```
┌─────────────────────────────────────────┐
│  출고 미리보기                          │
├─────────────────────────────────────────┤
│  LOT: 2024-LC-001                       │
│  요청 출고량: 5,000 kg                  │
│  ─────────────────────────             │
│  선택된 톤백:                           │
│  ✓ TB-001 (1,000 kg)                   │
│  ✓ TB-002 (1,000 kg)                   │
│  ✓ TB-003 (1,000 kg)                   │
│  ✓ TB-004 (1,000 kg)                   │
│  ✓ TB-005 (1,000 kg)                   │
│  ─────────────────────────             │
│  실제 출고량: 5,000 kg                  │
│  출고 후 잔량: 20,000 kg                │
├─────────────────────────────────────────┤
│  ⚠️ 경고: 없음                          │
├─────────────────────────────────────────┤

└─────────────────────────────────────────┘
```

## 6. 재고 조회

### 6.1 전체 재고 보기

**재고** 탭에서 전체 재고를 확인합니다.

| 컬럼 | 설명 |
|------|------|
| LOT 번호 | 고유 식별자 |
| 제품명 | Lithium Carbonate / Nickel Sulfate |

1. LOT 행 **더블클릭** 또는 **우클릭** → **상세보기**
2. 상세 정보 확인:
   - 기본 정보
   - 톤백 목록

## 7. 톤백 관리

### 7.1 톤백 조회

**톤백** 탭에서 전체 톤백을 조회합니다.

| 컬럼 | 설명 |
|------|------|
| 톤백 ID | 고유 식별자 |
| LOT 번호 | 소속 LOT |
| 중량 | 톤백 중량 (kg) |
| 상태 | AVAILABLE / SOLD |
| 생성일 | 생성 날짜 |

### 7.2 톤백 상태

| 상태 | 설명 | 재고 기여 |
|------|------|----------|
| **AVAILABLE** | 출고 가능 | ✅ 전체 중량 |
| **SOLD** | 출고 완료 | ❌ 0 kg |
| **RESERVED** | 예약됨 | ⚠️ 전체 중량 (출고 불가) |

### 7.3 톤백 무결성 검사

**메뉴** → **도구** → **톤백 무결성 검사**

검사 항목:
- inventory.current_weight = SUM(AVAILABLE 톤백 무게)
- SOLD 톤백의 재고 기여도 = 0
- 고아 톤백 (LOT 없는 톤백) 확인

## 12. 문제 해결

### 12.1 일반 오류

| 증상 | 원인 | 해결 |
|------|------|------|
| 프로그램 시작 안됨 | Python 미설치 | Python 3.10+ 설치 |
| DB 연결 실패 | 파일 손상 | 백업에서 복구 |
| PDF 파싱 실패 | API 키 오류 | API 키 확인 |

### 12.2 에러 다이얼로그 (v3.2)

오류 발생 시 새로운 에러 다이얼로그가 표시됩니다:

```
┌─────────────────────────────────────────┐
│  ⚠️ 오류 발생                           │
├─────────────────────────────────────────┤
│  출고 처리 중 오류가 발생했습니다.      │
│                                         │
│  ▼ 상세 정보                            │
│  ┌─────────────────────────────────┐   │
│  │ Traceback (most recent call...) │   │
│  │ ...                             │   │
│  └─────────────────────────────────┘   │
├─────────────────────────────────────────┤
│  [📋 로그 복사]  [📂 로그 열기]         │
│                         [🔄 재시도] [닫기]│
└─────────────────────────────────────────┘
```

- **로그 복사**: 에러 정보를 클립보드에 복사
- **로그 열기**: 로그 파일을 기본 편집기로 열기
- **재시도**: 실패한 작업 다시 시도

### 12.3 429 Rate Limit 오류

API 요청이 너무 많을 때 발생합니다.

**v3.2 자동 처리:**
- 시스템이 자동으로 요청 속도 감소
- 잠시 후 자동 복구

**수동 대응:**
- 30초 대기 후 재시도
- 동시 처리 파일 수 줄이기

## 14. FAQ

### Q1. LOT 번호 규칙이 있나요?
**A:** 시스템 제약은 없지만, `YYYY-제품코드-순번` 형식을 권장합니다.
- 예: `2024-LC-001` (2024년 Lithium Carbonate 1번)

### Q2. 톤백 수를 수동으로 조정할 수 있나요?
**A:** 입고 시에만 가능합니다. 입고 후에는 톤백 구조 변경이 불가합니다.

### Q3. 부분 출고가 안 되는 이유는?
**A:** v3.2부터 데이터 정확성을 위해 톤백 단위 전량 출고만 허용합니다.
이를 통해 재고 불일치 문제를 방지합니다.

### Q4. 출고 취소가 가능한가요?
**A:** 현재 버전에서는 직접 취소가 불가합니다. 
반품 처리로 재입고하거나, 관리자에게 문의하세요.

### Q5. 공유폴더에서 사용 시 느린 이유는?
**A:** 네트워크 지연으로 인한 현상입니다. v3.2의 부드러운 진행률 기능이 
체감 속도를 개선합니다.

### Q6. API 키 없이 사용 가능한가요?
**A:** 가능합니다. 단, PDF 자동 파싱이 불가하며 수동/Excel 입고만 가능합니다.

### Q7. 데이터 이전 방법은?
**A:** 
1. 기존 시스템에서 백업 생성
2. 새 시스템에서 복구
3. 또는 DB 파일(`sqm_inventory.db`) 직접 복사

### Q8. 동시에 여러 사용자가 사용 가능한가요?
**A:** 공유폴더에 DB를 두고 사용 가능하나, 동시 쓰기 시 충돌 가능성이 있습니다.
대규모 환경에서는 서버 버전을 권장합니다.

# 상태명 한글화 현황 및 Ruby 심화 질문 정리

**기준일:** 2026-02-22  
**목적:** 7개 메뉴 UI 적용 시 상태명 유지 여부 + Ruby가 제기한 “한글화 미반영”과의 관계, 심화 질문 3가지 답 정리.

---

## 1. 이 저장소(SQM_v592) 기준 — 이미 한글 상태명 적용됨

**현재 코드에서 “판매가능 / 판매배정 / 판매화물 결정 / 출고”는 이미 사용 중입니다.**

| 위치 | 내용 |
|------|------|
| **gui_app_modular/utils/ui_constants.py** | `STATUS_DISPLAY`: AVAILABLE→판매가능, RESERVED→판매배정, PICKED→**판매화물 결정**, SOLD→출고 |
| **inventory_tab.py** | 필터/요약: 전체·판매가능·판매배정·판매화물 결정·출고 |
| **tonbag_tab.py** | 동일 5종 + 개수 표시 |
| **cargo_overview_tab.py** | 동일 + STATUS_LABEL_TO_DB 매핑 |
| **dashboard_tab.py** | 카드: 판매가능/판매배정/판매화물 결정/출고, “판매가능률” 미터 |
| **custom_menubar.py** | 도움말 STATUS 안내: 판매가능, 판매화물 결정, 판매배정 등 |
| **pdf_report_gen, lot_detail_dialog, tree_enhancements 등** | “판매가능” 문구 사용 |

즉, **이 저장소에서는** 별도 “0단계 한글화” 없이도 탭/필터/대시보드에서 한글 상태명이 나옵니다.  
Ruby 검토가 **v5.9.9.1** 또는 **업로드 파일(v6044 등)** 기준이라면, 그 빌드에는 “가용/Available”, “Sold”만 있을 수 있으므로 **그쪽에서는 한글화 패치가 필요**할 수 있습니다.

---

## 2. PICKED vs SOLD 구분

- **질문:** PICKED와 SOLD가 둘 다 “Sold”로 나오는 환경에서, “판매물품 선정” vs “출고”로 구분할지?
- **Ruby 권장:** Yes, 반드시 구분해야 운영 혼란 없음.
- **이 저장소:** 이미 구분됨. `STATUS_DISPLAY`: PICKED → 판매화물 결정, SOLD → 출고.  
  → **다른 빌드에서 한글화할 때** PICKED≠SOLD 로 표기하도록 반드시 적용하는 것에 동의.

---

## 3. 영어 병기 여부

- **질문:** Available, Sold 같은 영어를 없애고 한글만 쓸지, “판매가능(Available)”처럼 병기할지?
- **Ruby 권장:** 한글만. SQM Korea 내부 시스템이므로.
- **의견:** 동의. 이 저장소도 한글만 쓰고 있음. 다른 빌드에서 한글화할 때도 영어는 제거하는 쪽 권장.

---

## 4. 대시보드 “가용률” → “판매가능률” 등

- **질문:** 대시보드 카드의 “가용률”, “가용 LOT”를 “판매가능률”, “판매가능 LOT”으로 바꿀지?
- **Ruby 권장:** Yes, 용어 일관성 유지.
- **이 저장소:** dashboard_tab.py에서 이미 “판매가능”, “판매가능률” 사용 중. “가용”이 남아 있는 곳이 있으면 그때만 “판매가능”으로 통일하면 됨.

---

## 5. “판매화물 결정” vs “판매물품 선정”

- **현재 이 저장소:** PICKED 표기는 **“판매화물 결정”**으로 통일되어 있음.
- **루비님이 “판매물품 선정”**으로 통일 원하시면:  
  `ui_constants.STATUS_DISPLAY['PICKED']` 와, 탭/도움말에서 “판매화물 결정”을 검색해 **“판매물품 선정”**으로 일괄 치환하면 됨. 로직 변경 없이 문자열만 바꾸면 됨.

---

## 6. 0단계 vs 4단계 후 한글화

- **이 저장소:** 이미 한글 상태명이 들어가 있으므로, **7개 메뉴 UI만 적용**해도 상태명은 유지됩니다.
- **다른 빌드(v6044 등)** 에서 “가용/Available”, “Sold”만 있다면:
  - **0단계:** 메뉴/출고 4단계 전에, 상태명 한글화만 먼저 적용 → 이후 메뉴 개편 시 “상태명이 바뀌나?” 혼선이 없음.
  - **4단계 후:** 출고/메뉴 작업을 모두 마친 뒤, 상태명 한글화 패치 적용.  
  - **권장:** 범위가 작고 텍스트만 바꾸는 것이므로, **0단계로 먼저** 해 두면 “판매가능/판매배정/판매물품 선정/출고”가 처음부터 통일되어 관리하기 좋음.

---

**정리:**  
- 이 저장소(SQM_v592): 상태명 한글화는 이미 적용됨. 7개 메뉴 UI 적용만 하면 됨.  
- 다른 빌드: Ruby 권장대로 상태명 한글화를 별도 패치로 넣고, PICKED/SOLD 구분·한글만·가용→판매가능 용어 통일을 적용하면 됨.

## 1. 시스템 개요

| 항목 | 값 |
|---|---|
| **시스템명** | SQM 재고관리 시스템 (SQM Inventory Management) |
| **현재 버전** | v8.8.5 (2026-07-21) |
| **형태** | Windows 데스크톱 앱 (PyWebView) + 로컬 FastAPI 백엔드 |
| **사용자** | 광양 창고 직원 1~3명, 본사(서울) 1명 |
| **데이터 규모** | LOT 약 140건 / 톤백 약 1,540개 / 일일 입출고 10~20건 |
| **가동 시간** | 평일 08:00~18:00 (야간 미사용) |
| **백업 정책** | DB 자동 백업 + GitHub 일 1회 push |

### 기술 스택 (요약)
- **프론트엔드**: HTML/JS (커스텀, 프레임워크 없음) + WebView2
- **백엔드**: FastAPI + Uvicorn (로컬 127.0.0.1:8765~8799)
- **DB**: SQLite (WAL 모드)
- **AI**: Gemini / OpenAI / Claude API (선택적, OCR 자동화)

## 2. 실행 환경

### 2.1 하드웨어
- **OS**: Windows 10 또는 11 (64-bit, WebView2 런타임 설치 필수)
- **RAM**: 8 GB 이상 권장 (4 GB도 동작은 함)
- **저장공간**: 500 MB 이상 여유 (DB + 로그 + 백업)

### 2.2 소프트웨어
- **Python**: 3.14 (정확히 이 버전 — `C:\Python314\pythonw.exe`)
  - 다른 버전 설치 시 `r1.vbs` 의 `PY` 경로 수정 필요 (line 10)
- **WebView2 Runtime**: Microsoft Edge WebView2 (Windows 11 기본 설치, 10은 별도 설치)
- **필수 패키지**: `requirements.txt` 참조 (총 461개 의존성, GPL/AGPL 0건 — `docs/audit-report.md` 4번 참조)

### 2.3 실행 방법
| 경로 | 용도 |
|---|---|
| **바탕화면 바로가기** | 일반 사용자가 더블클릭하는 진입점 |
| **`SQM.vbs`** | 표준 실행 (콘솔 창 없음) |
| **`r1.vbs`** | 디버그 실행 (콘솔 표시) — 문제 진단 시 |
| **`run.bat`** | CMD 빠른 실행 (개발자용) |
| **`main_webview.py`** | 실제 코드 진입점 (직접 실행 비권장) |

### 2.4 포트
- 백엔드 API: `127.0.0.1:8765~8799` (자동으로 빈 포트 탐색)
- **외부 노출 절대 금지**. Windows 방화벽에서 inbound 차단 확인.

### 3.2 DB 스키마 (핵심 테이블)
- `inventory` (140 rows) — LOT 마스터
- `inventory_tonbag` (1,540 rows) — 톤백 단위
- `stock_movement` (140 rows) — 입출고 이력
- `container_info` (820 rows) — 컨테이너 메타
- `freetime_info` (820 rows) — 컨테이너 프리타임
- `document_pl` / `_invoice` / `_bl` / `_do` (140 each) — 선적서류
- `audit_log` (22 rows) — 감사 추적
- `parsing_log` (0 rows) — AI 파싱 로그 (P1, 자동 기록)
- `schema_version` (7 rows) — DB 스키마 버전

### 3.3 백업
- **자동 백업**: `data/db/backups/sqm_inventory_archive_YYYYMMDD_HHMMSS.db`
  - 트리거: 수동 (백업 메뉴에서) — `백업 생성` 버튼
  - 보존: 무제한 (디스크 부족 시 수동 정리)
- **수동 백업**: `data/db/sqm_inventory.db` 파일을 외장 드라이브에 복사
- **복구 우선순위**: ① 최근 자동 백업 → ② 수동 백업 → ③ GitHub latest

## 5. 계정·키 (위치만 기록 — **값은 절대 적지 말 것**)

> ⚠️ **이 섹션에 키 값을 적지 마세요. 분실/유출 시 즉시 회전(rotate) 필요.**

| 키/계정 | 위치 | 회전 주기 |
|---|---|---|
| **Gemini API Key** | `settings.ini` 의 `[Gemini] api_key` 또는 환경변수 `GEMINI_API_KEY` 또는 Windows keyring (`SQM_Inventory`) | 6개월 |
| **OpenAI API Key** | `settings.ini` 의 `[OpenAI] api_key` 또는 환경변수 `OPENAI_API_KEY` | 6개월 |
| **Anthropic API Key** | 환경변수 `ANTHROPIC_API_KEY` | 6개월 |
| **DB 비밀번호** (PG 사용 시) | 환경변수 `SQM_PG_PASSWORD` (현재 SQLite만 사용 중이므로 무관) | - |
| **Telegram Bot Token** | 환경변수 `TELEGRAM_BOT_TOKEN` (선택적 알림) | 1년 |

### 키 회전 절차
1. 새 키를 발급받아 환경변수에 먼저 등록 (이전 키와 동시 활성)
2. 프로그램 재시작 → 새 키로 자동 전환 확인
3. **24~48시간 후** 이전 키 폐기 (발급처에서 revoke)
4. `audit_log` 의 키 변경 이벤트 확인 (시스템이 자동 기록)

### 키 유출 의심 시 즉시 조치
1. 해당 키 발급처 접속 → **즉시 폐기 (revoke)**
2. 새 키 발급 → 환경변수 등록
3. Git 이력 `git log -p | grep -i 'api[_-]?key\|password'` 으로 과거 노출 확인
4. 노출된 과거 커밋은 **키 회전으로만 대응** (이력 수정 시도 금지 — git history는 불변)

## 6. 복구 절차 (비상 시)

### 6.1 프로그램이 안 켜져요 (회색 창도 안 뜸)

```powershell
# 1단계: 이전 인스턴스 모두 종료
Get-Process pythonw -ErrorAction SilentlyContinue | Stop-Process -Force

# 2단계: 잠긴 포트 확인
netstat -ano | findstr ":8765"
# → PID 확인 후 Get-Process -Id <PID> | Stop-Process -Force

# 3단계: 1분 대기 후 재실행
cd D:\program\sqm\SQM_inventory
.\SQM.vbs
```

여전히 안 되면:
```powershell
# 4단계: 디버그 모드로 실행 (콘솔 표시)
.\r1.vbs
# → 콘솔에 에러 메시지 표시. 캡처 후 IT 담당자 연락.
```

### 6.2 DB가 깨졌어요 (오류: `database disk image is malformed`)

```powershell
# 1단계: 즉시 서비스 중단 (DB 더 손상 방지)
Get-Process pythonw -ErrorAction SilentlyContinue | Stop-Process -Force

# 2단계: 최근 백업으로 복원
$latest = Get-ChildItem D:\program\sqm\SQM_inventory\data\db\backups\ -Filter "*.db" | Sort-Object LastWriteTime -Descending | Select-Object -First 1
Copy-Item $latest.FullName D:\program\sqm\SQM_inventory\data\db\sqm_inventory.db -Force
# WAL/SHM 파일도 함께 정리
Remove-Item D:\program\sqm\SQM_inventory\data\db\sqm_inventory.db-wal -ErrorAction SilentlyContinue
Remove-Item D:\program\sqm\SQM_inventory\data\db\sqm_inventory.db-shm -ErrorAction SilentlyContinue

# 3단계: 재시작
cd D:\program\sqm\SQM_inventory
.\SQM.vbs
```

### 6.3 GitHub에 잘못 push 했어요

```powershell
# 1단계: 히스토리 확인
cd D:\program\sqm\SQM_inventory
git log --oneline -20

# 2단계: 직전 커밋 되돌리기 (작업 보존)
git revert HEAD --no-edit
git push origin main

# 3단계: 더 과거 커밋 되돌리려면 revert 연속 또는 reset (force push 위험 — 신중)
# → 운영자는 **반드시 IT 담당자 승인 후** force push
```

### 6.4 API 키 유출

→ **섹션 5 "키 유출 의심 시 즉시 조치"** 참조. **즉시** 폐기 + 회전.

### 6.5 디스크 풀 (DB 저장 실패)

```powershell
# 1단계: 가장 큰 폴더 확인
Get-ChildItem D:\program\sqm\SQM_inventory -Recurse | Sort-Object Length -Descending | Select-Object -First 20

# 2단계: 로그 정리 (보통 가장 큼)
Remove-Item D:\program\sqm\SQM_inventory\logs\sqm_inventory.log.* -ErrorAction SilentlyContinue
# sqm_inventory.log 는 회전 후 (절대 직접 삭제 X)

# 3단계: 백업 폴더 정리 (3개월 이전 것 제거)
Get-ChildItem D:\program\sqm\SQM_inventory\data\db\backups\ -Filter "*.db" | Where-Object LastWriteTime -lt (Get-Date).AddDays(-90) | Remove-Item
```

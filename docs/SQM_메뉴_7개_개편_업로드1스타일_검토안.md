# SQM 메뉴 7개 개편 — 업로드 1 스타일 UI 검토안

**작성일:** 2026-02-21  
**목적:** 기능은 최대한 유지한 채, UI만 “업로드 1” 스타일(개편안 7개 메뉴 구조)로 변경하기 위한 검토 보고서.  
**코딩은 하지 않고 검토안만 정리.**

---

## 1. “업로드 1” 스타일의 정의

- **업로드 1 스타일**이란, 과거 “업로드 1 / 업로드 2” 중 **업로드 1**처럼 **입고·출고를 역할별로 구분**하고, **“업로드 메뉴” 하나에 입고+출고를 섞어 넣지 않는** UI를 말합니다.
- v5.8.9에서 “업로드 2”가 제거된 뒤, 현재 **네이티브 메뉴**에는 여전히 **“📥 업로드 메뉴”**가 있어서, 그 안에 **입고 항목 + 출고 항목**이 한꺼번에 나열됩니다.
- **업로드 1 스타일로 간다** =  
  - **입고** 관련 기능은 “입고” 메뉴(또는 파일 안 “입고” 서브메뉴)에만 둠.  
  - **출고** 관련 기능은 “출고” 메뉴에만 둠.  
  - **파일** 메뉴 아래에는 “업로드 메뉴”를 두지 않고, 내보내기·백업·최근 파일·종료 등만 둠.

즉, **개편안에 나온 7개 탑레벨(파일 · 입고 · 출고 · 재고 · 보고서 · 설정/도구 · 도움말)** 구조가 곧 “업로드 1” 스타일 UI라고 보면 됩니다.

---

## 2. 현재 구조 요약

### 2.1 실제 노출 UI는 어디인가? (중요)

**실제 실행 시 사용자가 보는 상단 메뉴는 툴바(toolbar_mixin)입니다.**

- **근거:** `main_app.py` → `_setup_ui()` 안에서 **`_setup_toolbar()`만 호출**하며, `_setup_menu()`(custom_menubar / 네이티브 메뉴)는 호출하지 않음.
- 따라서 **7개 탑레벨 “업로드1 스타일” 적용 대상 = `gui_app_modular/mixins/toolbar_mixin.py`** 이고,  
  `_build_all_menus()` → `_build_inbound_menu()`, `_build_outbound_menu()`, `_build_file_menu()` 등만 손보면 1차 목표 달성 가능.
- custom_menubar / menu_mixin은 **현재 실행 경로에서는 사용되지 않음.** (툴바만 유지하고 두 메뉴는 비활성 상태로 두는 전략과 일치.)

### 2.2 툴바 vs 기타 메뉴 (참고)

| 구분 | 툴바 (toolbar_mixin) — **실제 노출** | 커스텀 메뉴바 (custom_menubar) | 네이티브 메뉴 (menu_mixin) |
|------|--------------------------------------|---------------------------------|-----------------------------|
| 탑레벨 | 📁 파일, 📥 입고, 📤 출고, 📊 재고, 📝 보고서, 🔧 설정/도구, ❓ 도움말 (7개) | 출고·파일·보고서·도구·v2.7·보기·도움말·품목 | 파일·보고서·… |
| 입고 | **_build_inbound_menu() — 하드코딩** ⚠️ | menu_registry | 📥 업로드 메뉴(혼합) |
| 출고 | **_build_outbound_menu() — menu_registry 사용** ✅ | menu_registry | 출고 서브 |
| “업로드 메뉴” | 없음 | 없음 | 있음 |

- **menu_registry.py**에서 `FILE_MENU_INBOUND_ITEMS`, `FILE_MENU_OUTBOUND_ITEMS`로 입고/출고 항목을 단일 정의하고 있음.
- **툴바 입고**만 menu_registry를 쓰지 않고 자체 하드코딩 → **입고도 menu_registry 기반으로 바꾸는 것이 안전** (Ruby 검토안과 동일 결론).

## 3. 목표 UI (개편안 59–186라인 기준)

- **탑레벨 7개:** 📁 파일 · 📥 입고 · 📤 출고 · 📦 재고 · 📊 보고서 · ⚙️ 설정/도구 · ❓ 도움말  
  (v2.7, 보기, 품목 등은 재고/설정/도구 안으로 흡수하거나 유지 여부만 결정)
- **📁 파일:** 내보내기(Ctrl+E), 백업(Ctrl+B), 최근 파일, 종료만. **“업로드 메뉴” 제거.**
- **📥 입고:** PDF 입고(원스톱) Ctrl+I, Excel 입고, D/O 후속 연결, 반품(재입고), 로케이션 업로드.  
  → 모두 **menu_registry 입고 항목 + 로케이션**으로 매핑 가능.
- **📤 출고:** 간편 출고(LOT) Ctrl+O, 배정표 출고, Allocation 예약/입력, Picking List 업로드, 바코드 스캔, Sales Order 업로드, Excel 출고(톤백 수), (옵션) 배치 출고.  
  → **menu_registry 출고 항목 + 기존 출고 전용 핸들러**로 매핑 가능.
- **📦 재고:** 새로고침(F5), 화면 전환(홈/재고/톤백/분석/로그), 품목관리, (옵션) 재고 경고·출고 예측, 테마 선택.
- **📊 보고서 · ⚙️ 설정/도구 · ❓ 도움말**  
  → 개편안 트리 그대로 두고, 기존 콜백만 연결하면 됨.

## 4. 기능 유지 원칙 (반드시 지킬 것)

1. **menu_registry 계속 사용**  
   - 입고·출고 항목은 `menu_registry.py` 한 곳에서만 정의.  
   - “📂 반품 입고 (Excel)”, “📋 Picking List 업로드 (PDF)”, “📋 Allocation 입력 (파일/붙여넣기)” 등이 **한 번만 정의**되고, 커스텀/네이티브 모두 동일 항목 표시.
2. **기존 콜백 그대로 사용**  
   - `_on_pdf_inbound`, `_bulk_import_inventory_simple`, `_on_return_inbound_upload`, `_show_return_dialog`, `_on_tonbag_location_upload`, `_on_allocation_input_unified`, `_on_picking_list_upload` 등 **이름·동작 변경 없이** 메뉴에서만 호출 위치를 바꿈.
3. **단축키 유지**  
   - Ctrl+I, Ctrl+O, Ctrl+E, Ctrl+B, F5 등은 `_setup_keyboard_shortcuts()`와의 바인딩을 그대로 둠.
4. **Excel/데이터 입력 원칙 유지**  
   - v6.0.4에서 정한 “데이터 붙여넣기 / 파일 업로드” 선택 흐름은 그대로 두고, 메뉴 라벨만 개편안에 맞출지 여부만 정하면 됨.

## 5. 적용 시 유의사항

| 항목 | 내용 |
|------|------|
| **네이티브 “업로드 메뉴” 제거** | menu_mixin에서 `upload_menu`(입고+출고 혼합) 제거. 대신 “입고” 탑레벨(또는 파일 안 입고 서브) / “출고” 탑레벨(또는 출고 서브)만 두고, 각각 `FILE_MENU_INBOUND_ITEMS` / `FILE_MENU_OUTBOUND_ITEMS`로 채움. |
| **커스텀과 구조 맞추기** | 개편안 7개 탑레벨을 적용할 때, custom_menubar는 이미 출고 탑레벨·파일 안 입고 서브가 있으므로, “입고”를 **탑레벨**로 올릴지(개편안과 완전 일치), 아니면 파일 안 서브로 둘지 선택 필요. |
| **누락 방지** | 반품 입고(Excel), 로케이션 업로드, D/O 후속 연결, Allocation 입력, Picking List, 바코드 스캔, Sales Order, 빠른 출고(붙여넣기), Excel 출고(톤백 수) 등 **개편안에 있는 항목은 모두** menu_registry 또는 기존 핸들러와 1:1 매핑되어 있어야 함. |
| **선택적 항목** | Sales Order 업로드 등 optional(앱에 메서드 있을 때만 표시)은 기존처럼 `len(entry) > 2 and entry[2]` 조건 유지. |
| **재고 / 설정·도구** | “재고” 탑레벨에 화면 전환·품목관리·테마 등, “설정/도구”에 PDF 변환·AI·DB 관리·고급 등 넣을 때, 기존 도구/보기/품목 메뉴의 콜백을 그대로 재사용. |

## 6. 권장 적용 순서 (구현 시 참고용)

1. **menu_registry는 수정하지 않고**, 입고/출고 항목만 “어디에 붙일지”만 바꿈.  
2. **네이티브 메뉴(menu_mixin)**  
   - 7개 탑레벨(파일, 입고, 출고, 재고, 보고서, 설정/도구, 도움말) 구성.  
   - “업로드 메뉴” 제거.  
   - 입고 탑레벨 → `FILE_MENU_INBOUND_ITEMS` + 로케이션 업로드.  
   - 출고 탑레벨 → `FILE_MENU_OUTBOUND_ITEMS` + 간편 출고, 배정표 출고, Excel 출고(톤백), (옵션) 배치 출고.  
3. **커스텀 메뉴바(custom_menubar)**  
   - 동일 7개 탑레벨로 재구성.  
   - “📥 입고”를 **탑레벨**로 올려 개편안 트리와 동일하게 맞추거나, 기존처럼 파일 안 “📥 입고” 서브로 유지(둘 중 하나 정책 결정).  
4. **재고 / 설정·도구**  
   - 개편안 트리(59–186라인)에 맞춰 기존 보기·도구·품목·v2.7 항목을 재배치하고, 콜백만 연결.  
5. **테스트**  
   - 커스텀/네이티브 모두에서 입고·출고·반품 입고(Excel)·로케이션·Allocation·Picking List 등이 한 번씩만 노출되고, 동작이 동일한지 확인.

## 7. 결론

- **기능은 전부 유지**하고, **UI만 “업로드 1” 스타일(개편안 7개 메뉴)**로 바꾸는 것은 가능합니다.  
- 핵심은  
  - **“업로드 메뉴” 제거**,  
  - **입고 / 출고를 역할별로 분리**해 각각 탑레벨(또는 명확한 서브메뉴)로 두고,  
  - **menu_registry 기반**을 유지하는 것입니다.  
- 이 검토안대로 적용하면, 사용자는 “업로드 1”처럼 **입고는 입고 메뉴, 출고는 출고 메뉴**에서만 찾으면 되고, 파일 메뉴는 내보내기·백업·종료 등으로 단순해집니다.

이후 코딩 단계에서는 위 순서와 원칙만 지키면 됩니다.

## 8. 대규모 적용 시 혼선 방지

이 작업은 **메뉴 구조 전반**을 건드리므로, 나중에 “어디를 바꿨는지”, “어떤 메뉴가 어떤 콜백이었는지” 헷갈리기 쉽습니다. 아래를 지키면 혼선을 줄일 수 있습니다.

### 8.1 한 번에 하지 말고 단계로 나누기

| 단계 | 범위 | 완료 기준 |
|------|------|-----------|
| **1단계** | **네이티브만** 7개 탑레벨 + “업로드 메뉴” 제거 | menu_mixin에서 입고/출고 각각 메뉴로 분리, 실행 후 모든 항목 클릭 시 기존과 동일 동작 |
| **2단계** | **커스텀** 7개 탑레벨 정렬 (입고 탑레벨 여부 결정) | custom_menubar가 개편안 트리와 동일한 순서·계층 |
| **3단계** | 재고 / 설정·도구 / 보고서 / 도움말 재배치 | v2.7·보기·품목 등이 재고·설정 안으로 이동, 콜백 유지 |
| **4단계** | 검수 + 문서 정리 | 체크리스트 전 항목 확인, 이 검토안·RELEASE_NOTE 업데이트 |

한 단계 끝날 때마다 **커밋**하고, “메뉴 7개 개편 1단계: 네이티브 업로드 메뉴 제거”처럼 **커밋 메시지에 단계 번호**를 넣어 두면, 나중에 롤백·추적이 쉽습니다.

### 8.2 구현 전·후 체크리스트 (혼선 방지용)

구현 **전**에 아래 표를 복사해 두고, 구현 **후**에 하나씩 체크하면 “빠뜨린 메뉴”를 줄일 수 있습니다.

**입고 (menu_registry + 로케이션)**

- [ ] PDF 스캔 입고 (Ctrl+I)
- [ ] 엑셀 파일 수동 입고
- [ ] D/O 후속 연결
- [ ] 반품 입고 (Excel)
- [ ] 반품 (재입고) 다이얼로그
- [ ] 로케이션 업로드 (톤백 위치 매핑)

**출고 (menu_registry + 추가 항목)**

- [ ] Allocation 입력 (파일/붙여넣기)
- [ ] Picking List 업로드 (PDF)
- [ ] 바코드 스캔 업로드 (CSV/Excel)
- [ ] Sales Order 업로드 (Excel) [optional]
- [ ] 빠른 출고 (붙여넣기)
- [ ] Excel 출고 (톤백 수) / 배정표 출고 / 배치 출고 (있는 경우)

**파일**

- [ ] 내보내기 (Ctrl+E) 서브메뉴
- [ ] 백업 (Ctrl+B) 서브메뉴
- [ ] 최근 파일
- [ ] 종료
- [ ] **“업로드 메뉴”가 없음** (중요)

**재고 / 보고서 / 설정·도구 / 도움말**

- [ ] 새로고침(F5), 화면 전환, 품목관리, 테마 등 기존 기능이 새 메뉴 위치에서 동작
- [ ] 단축키 Ctrl+I, Ctrl+O, Ctrl+E, Ctrl+B, F5 동작 유지

### 8.3 코드 안에서 헷갈리지 않게

- **menu_registry.py**  
  - 이 파일은 **항목 정의만** 담당. “어느 메뉴에 붙일지”는 menu_mixin / custom_menubar에서만 결정한다고 주석으로 한 줄 적어 두면, 나중에 “항목 추가는 어디지?” 할 때 찾기 쉽습니다.
- **menu_mixin.py, custom_menubar.py**  
  - 각 탑레벨 메뉴를 만드는 함수(`_create_file_menu`, `_create_inbound_menu` 등) **마다** 상단에  
    `# 7개 개편: 입고 탑레벨. 항목은 menu_registry.FILE_MENU_INBOUND_ITEMS`  
    처럼 **역할과 데이터 소스**를 한 줄씩 적어 두면, 6개월 뒤에 봐도 “입고는 registry에서 가져온다”는 게 바로 보입니다.
- **“업로드 메뉴” 제거**  
  - upload_menu를 지울 때, “제거 이유: 업로드 1 스타일 — 입고/출고는 각각 입고·출고 메뉴로 이전” 같은 주석을 한 번 남겨 두면, 왜 없어졌는지 나중에 이해하기 쉽습니다.

### 8.4 정리

- **단계 나누기** + **단계별 커밋** + **체크리스트** + **주석(데이터 소스·제거 이유)** 만 해 두어도, 대규모 코딩 후 혼선을 상당히 줄일 수 있습니다.
- 이 검토안과 `SQM_메뉴_7개_개편안_의견.md`를 함께 두고, 구현 시 두 문서를 참고하면 “원래 목표”와 “주의할 점”을 잊지 않고 진행할 수 있습니다.

## 9. Ruby 검토안과의 정합성 및 상태명 유지

### 9.1 Ruby 검토안에 대한 정리

- **실제 UI = 툴바**  
  - Ruby 결론과 동일. `main_app._setup_ui()` → `_setup_toolbar()`만 호출하므로, **변경 포인트는 toolbar_mixin 한 곳**으로 보는 것이 맞음.
- **입고도 menu_registry 기반**  
  - 툴바 `_build_inbound_menu()`가 현재 하드코딩이므로, **FILE_MENU_INBOUND_ITEMS 기반으로 재구성**하면 입고/출고 단일 정의가 깨지지 않음. Ruby 권장과 동의.
- **루비리 option 2 vs 3**  
  - 툴바 파일 메뉴에서 루비리 양식을 option=2로 호출하는 부분은, ExportHandlersMixin 정의(option=3)와 맞추는 것이 맞음. UI 개편 시 함께 정정 권장.
- **파일 메뉴 경량화**  
  - Gemini/PDF 변환을 설정·도구로 이동, 파일은 내보내기/백업/최근/종료만 두는 방향에 동의. 리스크 없음.
- **재고 vs 보고서 재정의**  
  - 툴바 “재고” 드롭다운이 현재 Excel 내보내기·이력·차트·명세서를 담고 있으므로, “재고 = 화면/조회 중심”, “보고서 = PDF·명세서·일일/월간”으로 재배치하는 Ruby 제안에 동의.

### 9.2 “판매가능 / 판매배정 / 판매화물 결정 / 출고” 상태명은 사라지나?

**사라지지 않습니다.**

- 이번 개편은 **상단 메뉴(진입 경로)** 만 정리하는 것이고,  
  **상태명(판매가능/판매배정/판매화물 결정/출고)** 은 **탭**(재고 리스트, 톤백 리스트, 총괄 화물 리스트, 대시보드)과 **필터/뱃지**에서 쓰는 표기입니다.
- 해당 표기는 `inventory_tab.py`, `tonbag_tab.py`, `cargo_overview_tab.py`, `dashboard_tab.py`, `ui_constants.STATUS_DISPLAY` 등에 정의되어 있으며, **메뉴 구조와 무관**합니다.
- **주의:** 탭 자체를 제거하거나, “화면 전환” 연결을 빼거나, 상태 필터를 만드는 STATUS 리스트를 다른 것으로 덮어쓰면 그때는 안 보일 수 있음. 따라서 **메뉴만 바꾸고 탭/상태 필터 구조는 유지**하면 상태명은 그대로 유지됩니다.
